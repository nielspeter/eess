New: `sections(corpus)`, a rule over sections (plan 0496). Each heading not inside a list item, blockquote or footnote, at any depth, is an element, `MdSectionElement`: its `name`, `depth`, `line`, the headings that enclose it (`sectionPath`) and `endLine`, the line before the next heading at its depth or shallower. Selectors `areNamed(name)`, `areAtDepth(depth)` and `areInSection(name)`; `haveSubsection(name, { depth? })` in both phases; `haveTable({ columns })`, every selected section holds such a table (a `section` option is refused); `notExist()`. A heading inside a list item, a blockquote or a footnote definition does not start a section, and a rule names it rather than reading past it. Types: `MdSectionElement`, `SubsectionOptions`, `SectionTableOptions`, `SectionRuleBuilder`.

New: `haveSection(name, { depth })`, on the condition, `docs().haveSection()` and `predicateHaveSection()`: only a heading at that level counts, and a heading of the name at another level is named in the finding. A depth that is not an integer from 1 to 6 is refused with an `ArchConfigError`. Type: `HaveSectionOptions`. Without the option, verdicts are unchanged; a `missing section "X"` finding gains a note when a heading of the name sits in a list item or blockquote.

New: one section-name scan for every corpus builder. Every section name a rule reads (`sections()`' selectors and `haveSubsection`, `links().areInSection()`, `haveSection` with a `depth`) is scanned in the documents the rule can see (those its `inDocuments` scopes admit, every document when it has none): a heading that misses a string name only by case or spacing, a heading of the name inside a container, or present only at other depths. A condition's finding names such a heading itself, and the scan does not repeat it. `links().areInSection()`'s case/spacing findings are unchanged for a rule with no `inDocuments` scope; a scoped one no longer reports a near miss in a document its scope excludes.

**Breaking:** a section name given as a `RegExp` with the `g` or `y` flag is read without it (bug 0506's eess-md half). The flag made `.test()` carry `lastIndex` from one heading to the next, so `docs().haveSection(/^Phase \d/g)` skipped every other document, and a table's `section` and `links().areInSection()` likewise. A rule that skipped documents can now report them. To migrate: drop `g`/`y` from section names; nothing else changes. Crossvalidate's own section matcher drops `g`/`y` too since #251; it takes eess-md only as an optional peer, for types, so it does not move with this release.
