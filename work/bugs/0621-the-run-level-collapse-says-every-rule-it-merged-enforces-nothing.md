# Bug 0621: the run-level collapse says every rule it merged enforces nothing

## Status

- **State:** Draft — measured 2026-11-05 on `main` at 046afd0c (v0.17.0) against the built
  packages; no red test yet.
- **Severity:** Medium — the verdict is right and the finding is shown once, but its message states
  something false about the reader's rules, and an author who believes it goes looking for rules
  that "cannot enforce anything" when every one of them does.
- **Origin:** inbound · a consuming project, 2026-11-05, measuring a question about findings
  repeated per rule ([proposal 027](../proposals/027-a-finding-says-whose-it-is-and-a-run-reports-it-once.md)).
- **Reported:** 2026-11-05

## Symptom

A closed record in `work/plans/completed/` holds `- [?] deferred→BUG-1` under `## Acceptance`, and
`[?]` is no declared box mark. Two `taskItems()` rules (`areOpen()`, `inDocuments(…)`,
`inSections(sectionsNamed(/^Acceptance$/))`, `notExist()`) and `honestyAtClose` each report the
same `md/undeclared-box-mark` finding, with the same file, line and element: three findings, as
[ADR-021](../../adr/021-a-predicate-that-cannot-judge-a-subject-says-so.md) rule 5 intends ("one
per cause per rule"). `dedupeConfigFindings`, which `eess-ts check` runs over a whole run
(`packages/ts/src/cli/commands/check.ts:238`), collapses the three to one, and appends:

> This one option generated 3 rules that cannot enforce anything; they are not listed separately
> because they are one edit.

None of the three rules was generated by an option, and each of them enforces: the first two judge
every readable open box in their scope, and `honestyAtClose` judges the record's ledger.

## Root cause

`affectedNote` (`packages/core/src/dedupe-config-findings.ts:56`) was written for the fan-out
ts-archunit's plan 0074 measured, inherited with the engine: one preset option
that generates many rules, each of which a dead glob leaves unable to enforce anything. `keyFor`
(`packages/core/src/dedupe-config-findings.ts:116`) collapses every finding with `bypassFilters`
set, so the note is attached to every configuration finding class the kernel and the dialects
emit: an unread box mark, an undecided subject
([ADR-021](../../adr/021-a-predicate-that-cannot-judge-a-subject-says-so.md)), an instrument that
ran out ([ADR-016](../../adr/016-a-bounded-instrument-limits-knowledge-never-the-verdict.md)). For
those the rules are hand-written, not generated, and they still enforce everything else.

## Fix

Not designed. The note says what the collapse knows: how many rules reported this one finding.
Whether those rules can enforce anything is the finding's own message to say, not the collapse's.
The fix measures the note on each configuration finding class the collapse merges, the preset
fan-out included, so the case it was written for keeps its meaning.
